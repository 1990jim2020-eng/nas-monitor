# 配置与凭据：作用、获取与保管

所有真实值属于接收方自己的环境。本包没有作者的口令、SSH 私钥、域名配置、账户文件或生产 .env。接收方 AI 不应尝试恢复它们。

## 统一获取方式

用户直接在本地 .env 或独立 secret 文件填写。AI 只核对字段名、是否非空、权限、路径映射和服务连通性；不要打印密钥、输出完整环境变量、读其他项目找“能用的密码”，也不要把含秘密的文件交给外部模型。

先明确目标容器/主机，再核实 Mounts。下面的 /run/secrets、/app/secrets 是容器内约定，宿主挂载源由接收方选择；两者不是同一个路径。真实 .env 不进入镜像 COPY，不进 Git，不进交付压缩包。

## 必需配置与主机指标

| 配置 | 作用 | 接收方如何获得 |
| --- | --- | --- |
| APP_API_TOKEN / WEB_API_TOKEN | App/Web 调用后端的访问口令，互相独立，也可仅设一个 | 用户在本地用 openssl rand -hex 24 生成，至少设一个有效值；Web/App 输入匹配口令 |
| NAS_HOST / NAS_GLANCES | 本机标签与 Glances v4 指标源地址 | 核实 Glances 运行主机、端口和 Docker 网络；NAS_GLANCES 是 URL，NAS_HOST 是主机地址 |
| NAS_MESH_IP / LAN_PREFIX | 延迟展示、局域网同 MAC 地址选择 | 用户的 VPN/组网和 LAN 配置；留空时不要猜原作者网段 |
| API_PORT / HEALTH_PORT | 业务 8765、loopback 存活探针 8766 | 先检查端口冲突；Compose 内端口与 healthcheck 要同步 |
| MONITOR_BIND_ADDRESS / MONITOR_PORT | 宿主绑定地址/端口 | 默认 127.0.0.1；用户确认 LAN/VPN/反代后再设置 |
| BACKEND_ROOT | 快照与调度器状态数据根目录 | Compose 默认 /app/data，对应独立 named volume；核实 UID10001 可写 |

## 按需服务的地址与认证

| 配置 | 功能 | 获取途径、注意事项 |
| --- | --- | --- |
| HA_URL / HA_TOKEN | 传感器、温度、UPS 等 | HA 用户个人资料生成长期访问令牌；URL 需为实际 /api/states；用用户认可账号，先核对传感器映射 |
| ROUTER_HOST / ROUTER_BASE / IKUAI_PASS | iKuai WAN、设备和限速状态 | 用户路由器管理地址与其授权管理口令；源码默认用户名 admin 是厂商通用默认，不是作者账号；如当地账号不同需适配 |
| OPENWRT_WAN3_HOST / PORT / USER / PASSWORD / IFACE | OpenWrt WAN 流量 SSH 回填 | 用户提供自己的路由器 SSH 地址、专用用户与认证；检查本地实际接口名；源码此采集路径目前使用密码 |
| NAS_SERVICE_* / ALIYUN_SERVICE_* | 用户选定服务的 HTTP 探活 | 从候选服务实际 Ports/网络与用户文档确认完整 URL；空值禁用，不能仅因容器名相似自动接入 |
| ALIYUN_* / TENCENT_* | 兼容旧远程主机入口 | HOST、PUBLIC_IP、NAME、GLANCES 按用户自己的主机填写；没有就全空；一般主机也可用管理页新增 |
| ALIYUN_SECURITY_URL / TOKEN、TENCENT_SECURITY_URL / TOKEN | 远程安全摘要 | 用户自己的安全采集服务地址和令牌；本包不包含该远程服务的部署实现，没有该服务则禁用 |
| NEW_API_URL / GATEWAY_NEW_API_URL | New API 管理聚合入口 | 自建网关的实际 URL，核实版本和管理 API 权限；主要使用 NEW_API_URL |
| NEW_API_KEY | New API 模型探活凭据 | 用户在自己的网关生成 API key；权限尽量只限所需模型查询 |
| NEWAPI_ADMIN_TOKEN_FILE | 管理聚合专用令牌文件 | 用户从自己的管理平台按当前版本授权方式取得，写入本地 secret 文件；只挂该文件到配置路径 |
| ANYTHINGLLM_URL / API_KEY / WORKSPACE | 知识库归档与问答 | 用户知识库设置页生成 API key，并选自己的 workspace slug；无服务则留空 |
| WEB_BOOTSTRAP_CODE / EXPIRES_AT | 一次性 Web 登录码 | 用户本地随机生成 code 与 Unix 过期时间，空值禁用；仅 URL fragment 传递，POST 兑换一次 |

不同上游可能改变认证方式，AI 应先查当地已安装版本接口，不从源码假设任何已有口令。Token 轮换后同步更新相应客户端，不复用 SSH 密码作为 API Token。

## WorkBuddy 与上游用量

| 配置 | 功能与获取 |
| --- | --- |
| WORKBUDDY_BASE / WORKBUDDY_WAN1_BASE | 用户选定实例的实际 HTTP 入口，先核对 /status 等接口是否兼容 |
| WORKBUDDY_CONFIG / WORKBUDDY_WAN1_CONFIG | 后端真正读取的容器内 JSON 配置路径，默认 /run/secrets/workbuddy-config.json 等；由用户授权挂载自己的配置文件 |
| WORKBUDDY_CONFIG_FILE / WAN1_CONFIG_FILE | 历史部署所用宿主路径变量；基础 Compose 不消费它们，仅设置这些变量不会自动挂载 |
| WORKBUDDY_AUTH_DIR / WAN1_AUTH_DIR | 采集器实际读取的容器内账号文件目录；用户从自己的上游实例 Mounts 确认并授权只读挂载，不向聊天展示文件内容 |
| WORKBUDDY_STATE_FILE / STATE_DIR | 状态文件/目录，按代码读取键及用户实例实际格式设置；STATE_DIR 历史字段不能代替 STATE_FILE |
| WORKBUDDY_CONTAINER / WAN1_CONTAINER | 最近请求日志来源的容器名；只有明确授权 Docker 日志读取时设置自己的实例名 |
| PIPIO_BASE_URL / USER_ID / PIPIO2_USER_ID | 兼容用量采集接口的实际 URL 与用户自己的账户 ID；从自己的账号资料或管理员确认，不能沿用作者 ID |
| PIPIO_ACCOUNT_NAME / PIPIO2_ACCOUNT_NAME | 用户自定义显示名，不是认证凭据 |
| PIPIO_SECRET_DIR | 容器内管理令牌目录，默认 /run/secrets；本地文件分别只读挂到 pipio-admin-token.txt / pipio2-admin-token.txt |
| PIPIO_UPTIME_URL / WATCH_PREFIX / WATCH_MODELS | 用户选定可用性接口与模型过滤，默认无 URL 禁用；模型列表用逗号分隔 |
| NAS_MONITOR_SCHEDULER | 可选采集任务开关，默认 0；启用前逐项检查 Task 所有上游、定时测速等副作用 |
| NAS_MONITOR_CUTOVER* | 快照写入模式；先理解 shadow_store 的目标路径再启用，避免覆盖原有业务文件 |
| HERMES_JOBS_FILE | 可选任务展示 JSON，来自用户授权任务服务；默认 /app/secrets/hermes-jobs.json |

账号目录可能含 refresh token/cookie。只从用户选定的实例取得，不复制它们到源码或公开包。本基础 Compose 没有挂载这些文件，接收方需按勘察结果添加最小挂载、设置采集器实际读取的键，并保证 UID10001 只读可访问。

WORKBUDDY_STATE 优先于 WORKBUDDY_STATE_FILE，指向容器内具体 JSON 文件。WORKBUDDY_STATE_DIR 只作为历史模板说明，本源码不读取它；应直接设置实际文件键。

HA_CABINET_TEMPERATURE_ENTITY、HA_CABINET_HUMIDITY_ENTITY、HA_CABINET_POWER_ENTITY 从用户自己的 HA 开发者工具“状态”页面选取实体 ID，空值跳过。其余 nas_vol、nas_fan、UPS 等兼容实体命名也是适配约定，需要核对自己的映射。

ANYTHINGLLM_WORKSPACE 必须由用户选择工作区 slug。Web/App 文件上传与问答使用后端指定工作区，不在前端写死名称。

## Docker、测速与路径

DOCKER_GID 从宿主 socket 的 stat -c '%g' 获取；默认模板不挂 socket。DOCKER_SOCK 是部分采集器的容器内路径。Docker API 权限可控制宿主，无论 bind mount 是否 :ro。

SPEEDTEST_BINARY_HOST、SPEEDTEST_NETWORK、SPEEDTEST_WAN*_IP 必须由接收方根据自己的测速程序、Docker/macvlan 网络、路由规则核实。测速可能产生费用、流量并创建容器，用户未选择时保持空且调度器关闭。

Mihomo / WAF / 机场流量等历史扩展可能依赖特定容器内文件或自己的快照生成器。AI 应检查具体路由所读路径和文件格式，缺少服务时禁用该功能；基础模板不挂这些源。/mihomo 是约定容器路径，不代表宿主同名目录。

## 域名、SSH 与 Android 签名

- 域名由用户 DNS/反代配置确认；没有公网需求可以只用 LAN/VPN，不要求域名。不要猜作者域名。
- SSH 用户名由用户确认本机已授权账号；推荐创建专用账号与密钥。用户本地生成密钥并安装公钥，私钥留在设备安全存储。已有密码让用户直接在 App 设置填写。
- 跳板机仅在用户网络确实需要时配置；核验服务端主机密钥指纹，不能关闭 host key 校验来“连通”。
- App 首次启动设置自己的后端 URL 与 Token。SSH 密钥/口令由 SecureCredentialStore / Android Keystore 管理；Web Token 存在浏览器存储，应使用可信浏览器及 HTTPS/VPN。
- Android SDK 用 ANDROID_HOME 或用户自己的 local.properties；该文件不要入包。签名库由用户自行生成，keystore.properties 根据 example 本地填写；不使用作者签名或密码。

## 防止再泄露

.env 和 secret 文件建议 chmod 600（容器用户读取需按实际权限设计）。.gitignore 不能清除已跟踪的秘密。发布前扫描源代码、测试、注释、图片元数据、Git 历史和压缩包清单。

报告只能写“字段已配置/未配置、路径和验证结果”，不可写秘密值。若发现真实秘密曾发布，通知所有者撤销/轮换；不要仅删除文件就认为风险消失。
